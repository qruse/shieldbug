# Shieldbug 프레임워크 검토 (Claude, 2026-11-11)

## 1. 실측: 같은 최소 대시보드 서버의 대기 메모리 (이 PC, Windows 11, 12 논리코어)

| 런타임 | 작업관리자 메모리(전용 작업 집합) | 작업 집합 | 배포 크기 |
|---|---|---|---|
| Go 1.27 net/http | 2.0 MB | 8.3 MB | 실행 파일 5.8 MB |
| Python 3.11 http.server | 10.2 MB | 29.0 MB | 런타임 따로 필요 |
| Node 24 http | 14.8 MB | 39.8 MB | 런타임 따로 필요 |
| (참고) 점검 중 AI CLI: claude.exe | — | 285 MB | 사용자가 이미 설치 |

- Rust는 설치하지 않아 직접 재지 않음. 같은 서버면 1~2 MB 수준으로 알려져 있어 Go보다 1 MB 남짓 가벼움.
- 처음 잰 Go 수치(44 MB)는 첫 실행 때 백신 검사가 끼어든 값이라 버림. 두 번째부터 8 MB로 안정.

**결론 1:** 하루 한 번 점검할 때 AI CLI가 285 MB를 쓰므로, 언어에 따른 차이(1~15 MB)보다 **상주 프로세스가 없는 구조**가 체감 무게를 훨씬 크게 좌우함. 점검은 OS 예약 작업이 실행하고 끝나면 종료하고, 대시보드 서버는 열어 둔 동안만 뜸.

| 부류 | 이미 있는 것 | 걸림돌 |

| B. 데스크톱 앱만 쓰는 비개발자 (Claude 앱 Code 탭, Codex 앱) | 앱 안의 에이전트 | 터미널 모름. Python·Node 없음. 에이전트가 대신 설치해야 함 |

### 에이전트 자체 기능형만으로 안 되는 이유 (보안)
에이전트가 직접 셸로 설정 파일을 뒤지면, 점검 중에 읽은 웹 보안 경고문이나 파일 안의 프롬프트 인젝션이 그 셸 권한을 그대로 쓸 수 있음. 보안 도구가 공격 통로가 되는 셈.
→ **수집은 정해진 코드가(AI 없이), 판단은 AI가(파일·셸 권한 없이, 웹 검색만)** 나누는 구조가 안전함. 이 분리가 "점검 중 AI는 읽기 전용"의 실제 구현임.

## 4. 추천안

- **주력: Go 실행 파일 하나** (외부 라이브러리 0, 표준 라이브러리만)
  - 윈도우·맥·리눅스 × x64·ARM64를 GitHub Actions로 빌드하고 SHA-256 체크섬을 같이 올림.
  - 점검 항목·수집 명령·프롬프트는 **JSON·텍스트 파일**로 빼서, 커스텀은 재컴파일 없이 "AI한테 이 파일 고쳐 줘"로 끝냄.
  - 상주 없음: 점검은 OS 예약 작업이 하루 1회 실행 후 종료하고, 대시보드는 `shieldbug` 실행 중에만 127.0.0.1에서 뜸(일정 시간 안 쓰면 스스로 꺼짐).
- **대비책**
  - D(백신이 실행 파일 차단): Go가 있으면 소스에서 직접 빌드하고, 없으면 에이전트가 Go를 사용자 폴더에 내려받아 빌드(관리자 권한 불필요).
  - C(브라우저 없는 서버): `shieldbug report`로 HTML 파일 하나를 만들거나 SSH 터널로 대시보드를 봄.
  - 에이전트 예약 기능은 "보조 알림"으로만 씀(결과 요약을 휴대폰으로 보내는 정도).
- **Rust에 대한 답:** 좋은 언어고 메모리도 제일 적지만, 이 프로젝트에선 실제 무게를 정하는 게 AI CLI(285 MB)라서 Go 대비 1 MB 절약은 의미가 없음. 대신 빌드·기여 난도가 올라감. 나중에 사용자가 많아지고 수집기만 따로 떼어 낼 때 다시 검토.
